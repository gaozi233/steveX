# 实体放置验收：2026-10-23

环境：原版 Minecraft 1.21.11、Mineflayer 4.39.0，专用生存测试玩家，Brain 关闭。通过正式 HTTP 命令入口 `equip → lookat → placeentity` 测试。RCON 只搭建夹具和读取服务端真值，不给生产 Agent 增加服务端权限；未调用 LLM 或使用 API Key。

## 实机场景

每次发放 2 个物品，数量跨槽求和；成功后服务端确认剩余 1，失败后核对实际数量及 API 差值。成功的 `entityUUID` 用于服务端定向读取 `Pos`，与 API 冻结的生成位置对照；实体会运动，所以不是同 tick 对比。夹具在生成后关闭测试实体 AI，位置差要求小于 0.65 格；另对陆地船水平位置、侧面猪和水晶位置做专项断言。

## 发现并修复

1. 上游 `placeEntity` 对船额外发送的 use_item 缺少 1.21.11 必需旋转字段，触发协议序列化错误；它还等待旧统一实体名 boat，而当前协议区分船材质。船／筏改用 Mineflayer 原生 `activateItem`，由该入口处理 sequence 和 rotation，不手写协议包；其余实体物品用 `_genericPlace`，保留实际命中点和面。
2. 上游生成监听注册在交互之后，且遇到首个不匹配实体也会移除。现在先注册，筛选本次交互前不存在的 ID、注册表对应类型及近邻范围；无关实体不会终止等待。多个候选返回 AMBIGUOUS_ENTITY_SPAWN，不随意认领。
3. 原来异常后丢失生成和库存效果。现在即使超时／交互异常／取消，也核对最终库存并保留已观察的生成；库存无法确认为 null，不冒充零消耗。断线不再额外等待必然失败的库存快照。
4. 生成位置在事件到达时复制，避免实体随后移动使返回位置漂移。后续当前位置仍应通过 nearby 等查询，不将生成位置当实时位置。
5. 近距离瞄准水晶底座顶面时，查询射线使用身体高度，而 lookat 使用眼高，导致 NO_TARGET。现有 raycast_compat 在 Mineflayer 4.39.0 下优先使用 eyeHeight，保留零角度修复及无眼高时的兼容路径；有站立／潜行眼高替身回归。升级依赖须复审。

## 失败语义

| errorCode | 含义 |
| --- | --- |
| INVALID_ARGUMENTS / WINDOW_OPEN | 无参数命令；须先关闭窗口 |
| INVENTORY_SYNC_FAILED | 初始库存未同步，没有发送本次交互 |
| UNSUPPORTED_ITEM / NO_TARGET / INTERACTION_UNAVAILABLE / INVALID_SURFACE | 持物／准星／原生接口／水晶底座条件不满足，交互前拒绝 |
| ENTITY_SPAWN_NOT_CONFIRMED | 5 秒内没有观察到匹配的新实体，不等于没有副作用或一定没消耗 |
| AMBIGUOUS_ENTITY_SPAWN | 多个匹配新实体，无法可靠归属 |
| ITEM_CONSUMPTION_NOT_CONFIRMED | 观察到生成，但生存模式未确认消耗 1 |
| ENTITY_INTERACTION_FAILED | 发送交互异常，保留可核对的效果 |
| INVENTORY_CONFIRMATION_UNAVAILABLE | 最终库存未知，changes=null；已见生成仍保留 |
| CANCELLED / DISCONNECTED | 取消／断线，不自动重试；保留已知事实 |

失败 `output` 同时包含错误码、已观察实体及库存变化，供 Brain／LLM 阅读。创造模式不要求物品减少。画保持明确不支持，不增加路径规划、自动重试或自动回滚；刷怪笼配置也不纳入“生成实体成功”。
