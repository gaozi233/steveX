## 发现与修复

1. **氧气来源与尺度混淆。** 初查 `/state` 曾出现 oxygen=149，文本查询出现 6/20，但附近未找到水。原兼容层按数值大小再次缩放，且依赖已可能被其他实体污染的 Mineflayer 值。改为只从自身 `air_supply` 原始 tick 更新，300 tick 对应 20 个内部单位；非自身／不含空气字段的包不能替换自己的读数。未收到自身数据时保持 null，不猜测满氧。文本查询去掉第二次缩放。已补低空气、部分元数据、附近实体污染及未知值回归；后续水下实测见文末专项记录。
2. **非有限数值可穿透校验。** look/lookat 原先只检查 NaN，Infinity 会通过。现拒绝非有限数值；pitch 限制为正负 PI/2，并说明单位为弧度。yaw=0 朝 -Z，正 pitch 向上。
3. **移动时长部分解析。** parseInt 会把 100abc 当作 100；现在必须为完整整数，范围 1..30000 毫秒。返回确切毫秒数，避免 150ms 被四舍五入显示为 0.1s。
4. **nearby 不是“附近”。** 原实现直接取已加载实体前 20 个，曾列出 160 米外实体。新增默认 32 格半径、1..128 格校验、按距离排序、玩家用户名过滤和结构化实体列表。仍受客户端实体加载范围限制，不是世界全局搜索。
5. **诊断与完成语义不足。** `/state` 新增朝向、运动状态、显式七键状态、原始空气 tick 和局部碰撞方块。控制状态逐键读取，不能 JSON 序列化原非枚举 getter 后得到空对象就判定停止。jump 明确表示“200ms 后释放，不等待落地”，落地由任务验收单独判断。

`move` 是定时按键，不是精确位移控制。实测同为 150ms 仍有约 0.43..0.86 格差异；服务端 tick、客户端物理步数及惯性等均可能影响结果，不能仅凭本轮定位具体贡献。精确位置任务应使用有到达判定的路径规划，再独立验收 `goto`。
