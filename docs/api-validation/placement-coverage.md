## 必须保留的执行语义

放置成功要观察服务端方块变化或新实体生成，并核对生存物品消耗。同类型状态变化不能只比较名称；门／床不能只确认一半；失败也返回实际消费，未知不是零消费。新右键只选择一条交互路径，不在失败后回退、连点或自动换手。

| 放置错误码 | 解释 |
| --- | --- |
| ENTITY_SPAWN_NOT_CONFIRMED | 未观察到匹配的新实体，不代表没有消耗或副作用 |
| AMBIGUOUS_ENTITY_SPAWN | 多个匹配候选，不能随意认领 |
| ITEM_CONSUMPTION_NOT_CONFIRMED | 已观察生成，但生存消耗未确认 |
| INVENTORY_CONFIRMATION_UNAVAILABLE | 最终库存未知，changes=null，保留已观察事实 |
| INVALID_SURFACE / UNSUPPORTED_ITEM | 底座或持物不支持，不能靠重复发送解决 |
| CANCELLED / DISCONNECTED | 保留已有事实，不自动重试可能已经消费的动作 |

位置／朝向同步、取消、服务器拒绝、监听清理及错误反馈有自动回归，不替代所有材质／朝向、高延迟、其他协议和多人并发实测。mine／collect 的受保护寻路边界见主清单及 [采集合成契约](../gather-build-contract.md)，不是本放置表的独立全量复测。
