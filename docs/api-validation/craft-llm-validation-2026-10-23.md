# 新版 recipes／craft 的 DeepSeek 实试

## 范围

按用户最新要求，取消严格的改进前后对照，直接试试新版。未启动旧版服务，也没有旧版模型调用；不把本轮与历史单次结果的差异解释为改进收益。

复用既有基础 5 项和复杂 7 项任务，每项运行一次。模型为 deepseek-v4-flash，任务提示词沿用试试清单；使用新版 API 描述及真实返回结果。保留生产 Brain 最近 10 条完整历史，不增加专用记忆、配方搜索器或预写合成步骤。

基础组每项最多 12 次、整组 60 次模型调用；复杂组每项最多 36 次、整组 140 次。全部合计最多 200 次。只有固定工作台和初始背包，不允许采集、烧炼或外部补料；没有试试多 Agent 并发。

## 统计口径

- 完成：客户端背包与服务端 Inventory／clear <item> 0 无损计数核对；正常任务要求最终同时持有目标数量，缺料任务要求正确 BLOCKED，不能把拒绝算成成功合成。
- 查询覆盖：是否读取了目标目录，或使用预置的当前可用候选列表；独立保留在原始 assessment 中。
- 条件不满足的调用：实际由模型发起、API 拒绝的合成／配方查询。与参数格式错误、执行故障分别检查，不能把全部拒绝都算成接口 bug。
- 预置失败：恢复与候选选择任务由夹具主动触发，单独记录，不计作模型错误。
- 重复查询：本任务内同一 recipes 命令第一次之后的出现次数；不含 Brain 自动读取的 inventory 等状态查询。
- 无效回复：Brain 解析拒绝与试试安全白名单拒绝分开记录；不混同服务端执行错误。
- 调用次数含未被解析成命令的模型回复，不等于成功执行次数；字符数不当作 token 或费用。

## 问题与处理

### 一次不可执行的 hand 合成

混合木材任务中，模型发出 `craft iron_ingot 1 hand`。当时背包有 9 铁粒，所需配方依赖工作台，所选模式不可执行。API 返回 RECIPE_QUERY_REQUIRED，明确 Nothing crafted、当前检查范围及目录查询入口；没有消耗材料。模型随后 `recipes iron_ingot`，再使用 table 完成。

这是一次条件不满足的调用，不是参数语法错误或执行器故障。它说明反馈能支持本例恢复，但不能保证 LLM 永远不误选模式，也不能确定恢复只归因于某个新增字段。不为这一次错误增加自动规划或专用记忆库。

### 中文标点被验收器误拒

缺料场景中模型正确指出 27 铁锭当量不足 31，却使用 `say BLOCKED：说明` 的全角冒号。生产 say 接口允许该文本，但旧试试白名单只识别空白和英文冒号，误拒两条有效响应并继续调用，最终才接受简短 BLOCKED。

只修试试脚本：结束标记支持大小写及 Unicode 标点边界，仍拒绝多行命令和不在白名单的动作；普通 inventory／recipes／craft 的参数交给真实 API 校验，不再由试试器施加一套更窄的数字／名称语法。API 与 Brain 策略没有为这轮任务修改。

两条原始响应曾离线重放并接受为 BLOCKED。专项实际复试 2 次调用通过、无白名单拒绝，服务端确认无铁砧且 3 铁块未消耗。该次恰好返回简短 BLOCKED；全角标点识别由回复回放和自动试试另行验证。原轮的 4 次与专项的 2 次都计入实际调用成本，没有改记为“原轮只用了 2 次”；原始过程日志现已清理。

## 验证与限制

试试器修复后自动回归 182/182 通过。生产 recipes／craft 本轮保持不变，没有针对具体任务添加计划、材料预留、递归合成、专用记忆或上下文策略。临时旧版对照准备已撤销，没有运行旧版服务或生成对照成绩。

本轮每项一次，另有一次缺料专项，不提供统计意义的稳定成功率。没有严格控制采样随机性、模型服务端版本、网络时延或游戏时钟；也未重新试试未知返回物／最终确认失败的模型解释。这些边界仍以接口单元试试和机械验收为证，不把当前 12 项通过推广为“任何反馈都不会被误解”。

结果只适用于预置工作台、已有材料的串行任务，不包括采集、烧炼、容器取材、多人干扰、低 TPS、掉线或开放世界长程能力。试试物品和工作台已清理，试试玩家恢复原坐标朝向，服务继续运行。
