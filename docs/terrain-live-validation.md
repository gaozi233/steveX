## 调用与判定

- `move forward 2500`：按住前进 2.5 秒并释放。返回成功只证明命令完成，不代表走过跑道；查看轨迹、位移和服务端坐标。
- `jump`：按住跳跃 200ms；在半砖／楼梯上、水流中、气泡柱中分别测试。水中 jump 是水中移动输入，不应要求复制陆地跳高；气泡柱外力可能压过按键作用。
- `goto x y z`：验证路径执行与到达脚部方块。最多观察 12 秒，超限发送 stop，并单列 watchdog；不冒充 API 自身完成。
- 普通 move 与 jump 当前串行仲裁，不能用两个 HTTP 请求测试同时 W+空格。本轮没有覆盖并发组合按键。
- 气泡柱里通过目标位置不等于能在目标高度悬停。goto 即使成功，也只报告返回时达到目标方块，不承诺对抗持续水流维持位置。

## 结果

| 地形 | move / jump | goto | 判定边界 |
| --- | --- | --- | --- |
| 平地 | 前进约 11 格；原地跳跃后落地 | 到达 | 首轮有效轨迹；人工对照待签字 |
| 底半砖 | 前进跨上跨下；从半砖跳起并落回 | 到达 | 未见本跑道卡住；不推广至所有半砖状态 |
| 直楼梯 | 前进升高 3 格；楼梯原地跳跃有高度变化 | 到达上层平台 | 跳跃落点受台阶形状影响 |
| 顺水流（校准后） | 前进约 8.8 格；水中 jump 同时受流推动 | 到达且返回位置满足目标 | 水源挡板已加；早期双向流结果不作顺逆流对比 |
| 逆水流（校准后） | 前进约 4.7 格；jump 期间可被流推回 | 到达且返回位置满足目标 | 不同起点水深与入水距离，不能据此精确比较速度 |
| 上升气泡柱 | 采样到明显上升及出水后继续上冲 | 复测出现规划超时 | 基础浮力现象可见；柱内导航不可靠，不记通过 |
| 下降气泡柱 | 从水面被拉到底部；短 jump 不能阻止下拉 | 上游提前结束；修复后正确报未到达 | 已修返回语义，未解决稳定的柱内路径控制 |

表内 move/jump 的通过是对应物理现象可见，不是每条路线完整任务全部通过。用户的人工确认仍独立登记。

## 修复

1. `src/commands/actions/goto.js` 拒绝 Infinity/-Infinity 等非有限坐标。
2. 上游 `mineflayer-pathfinder/lib/goto.js` 会在部分空路径情况下 resolve；原 handler 无条件返回 Arrived。本轮下降柱出现返回成功但实际仍在目标上方，已补实际脚部方块目标检查；不满足则停止残留路径，返回 `ok:false`、position 与 target。
3. goto 成功响应也带实际 position 和向下取整后的 target，明确目标方块语义。没有修改 node_modules，也没有伪装完成尚不支持的水下路径。
4. 实机脚本增加显式 `--live`、`--lane`/`--action` 白名单与进程锁，防止自身重复运行；避免以 `test-` 前缀或 `-test` 后缀命名实机脚本，并在 Node 测试上下文不自动运行。

自动测试 `npm test`：99/99 通过。新增非有限参数、负坐标 GoalBlock 取整、上游 Promise resolve 但未到达的回归。原地形脚本曾被 Node 自动发现并与实测脚本冲突，已改名；冲突期间数据作废，不能用其判断碰撞兼容性。随后重连测试 bot 清除旧本地物理状态，并重新单进程实测。

## 复测

先启动本轮专用服务端与 manual-test HTTP 服务；脚本依赖本机忽略的 server.properties RCON 凭据，不包含通用生产服务器部署功能。

```powershell
# 仅复测现有半砖，不重搭场
node scripts/terrain-live-smoke.cjs --live --lane=slab

# 仅复测下降柱寻路
node scripts/terrain-live-smoke.cjs --live --lane=bubble-down --action=goto

# 重建整场，会替换预留区域方块并传送观察账号；先确认所有人离开跑道
node scripts/terrain-live-smoke.cjs --live --build --build-only
```

锁文件存在时先检查是否仍有脚本在跑；不要盲目删除锁叠加另一批实验。脚本会移动测试 bot、调用 stop，但不在结束后删除场地，方便人工继续核验。

人工同路线对照：先确认自身 survival、非飞行、无速度/跳跃药水且不疾跑，清空碰撞干扰；例如 `/tp @s 100.5 -60.0 8.5 -90 0` 后按 W 通过半砖，或 `/tp @s 105.5 -59.5 8.5 -90 0` 后原地跳跃。水流中按键与气泡柱都应单独测。若人工按键时长未记录，不报告严格速度一致。人工与 bot 不要同时占据同一狭窄跑道，以免实体碰撞混淆结果。

后续优先：人工比较气泡柱轨迹、独立的竖直水中控制策略、稳定驻留判定，再扩展楼梯朝向和组合按键；当前不能把气泡柱 goto 列为已支持能力。
